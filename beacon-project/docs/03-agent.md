# 03. 에이전트

> 최초 작성: 2026-09-23

## 1. 원칙

> **LLM은 행위자가 아니라 함수다.** (핸드오프 §1)

| LLM이 하는 일 | LLM이 하지 않는 일 |
| --- | --- |
| 읽기: 어떤 조회 도구를 부를지 고르고, 결과를 요약 | 쓰기 실행 |
| 쓰기: 사용자 발화에서 슬롯 값을 뽑고, 되물을 질문 제안 | 상태 전이 결정 |
| | 날짜·시각 계산 |
| | 대상 확정 (후보 제시까지만) |

LLM이 엉뚱한 답을 내도 할 수 있는 최악이 "쓸데없는 조회" 또는 "잘못된 되묻기"에 머물도록 설계한다.

## 2. 절충 구조 (D16)

사용자 발화 하나가 들어오면 먼저 **의도를 읽기/쓰기로 분류**하고, 경로를 나눈다.

```
발화 ─▶ NFKC 정규화 ─▶ 의도 분류 (LLM 1회)
                            │
              ┌─────────────┴──────────────┐
              ▼                            ▼
          ReadLoop                     WriteFlow
       (도구 호출 루프)                (상태 기계)
```

진행 중인 WriteFlow 세션이 있으면 분류를 건너뛰고 해당 세션으로 보낸다.

### 2.1 ReadLoop — 도구 호출 루프

```
LLM에 [시스템 프롬프트 + 대화 + 허용된 읽기 도구] 전달
  → LLM이 도구 호출 요청
  → 서버가 역할 검증 후 실행, 결과를 대화에 붙임
  → 반복 (최대 5회)
  → LLM이 최종 답변
```

- 부작용이 없으므로 LLM이 경로를 고르게 둔다
- 호출 상한 5회. 초과 시 현재까지의 정보로 답변
- 도구 반환은 행 수 상한(기본 50) + 집계 우선. 토큰 비용 통제

### 2.2 WriteFlow — 상태 기계

세션 상태와 허용 전이:

```
collecting  → collecting | confirming | aborted
confirming  → confirming | creating  | aborted
creating    → done | aborted
```

- `collecting`에서 `creating`으로 가는 경로가 **존재하지 않는다**. 승인을 건너뛸 방법이 구조적으로 없음
- `creating` 실패 시 되돌아가지 않고 세션 종료. 재시도는 새 세션 (응답만 실패하고 실제로는 생성된 경우의 중복 방지)

한 턴의 처리:

```
1. LLM 1회 호출: 발화 → { 채워진 슬롯, 되물을 질문 }
2. 코드: 시간 문자열은 규칙 파서로 실제 시각 계산 (§5)
3. 코드: 대상 이름은 이름 해석 규칙으로 후보 결정 (§6)
4. 코드: 슬롯이 다 찼으면 confirming으로 전이, 확인 카드 생성
         아니면 collecting 유지, 되묻기
5. 사용자 승인 → creating → kuma-bridge 호출 → done
```

### 2.3 점검 생성 슬롯

| 슬롯 | 필수 | 채우는 주체 |
| --- | --- | --- |
| 제목 | O | LLM (자유 문장) |
| 시작 시각 | O | LLM이 원문 추출 → 규칙 파서가 계산 |
| 종료 시각 또는 기간 | O | 동일 |
| 대상 모니터 | O | LLM이 이름 추출 → 이름 해석 규칙 |

## 3. 도구 카탈로그 (D20)

### 3.1 읽기

| 도구 | 파라미터 | 설명 |
| --- | --- | --- |
| `list_targets` | `status?`, `tag?`, `adapter?` | 현재 상태 목록 |
| `get_target` | `id` | 단건 + 최근 이력 |
| `get_uptime_summary` | `id?`, `period` | 가동률 |
| `list_status_events` | `id?`, `from`, `to` | 상태 전이 이력 |
| `list_maintenances` | `from`, `to`, `status?` | 예정·진행 점검 |
| `search_external_events` | `source?`, `region?`, `severity?`, `q?`, `from`, `to` | 수신된 웹훅 |
| `resolve_target` | `name` | 이름 → 대상 후보 (내부 규칙 적용) |

### 3.2 쓰기 (WriteFlow 전용)

| 동작 | 최소 역할 |
| --- | --- |
| 점검 생성 | Operator |
| 점검 취소 | Operator |

쓰기는 LLM의 도구 목록에 들어가지 않는다. 의도 분류가 쓰기로 판정하면 WriteFlow가 시작된다. Viewer의 발화가 쓰기로 분류되면 세션을 열지 않고 권한 부족을 안내한다.

### 3.3 노출하지 않는 것

사용자·역할 관리, 어댑터 설정, 알림 토글, 감사 로그 삭제. 관리 작업은 UI에서만.

## 4. 역할과 도구 필터링

- LLM에 넘기는 도구 목록 자체를 현재 사용자 역할로 거른다
- 실행 시점에 한 번 더 검증한다 (필터가 뚫려도 실행에서 막힘)
- 모든 도구 호출은 사용자·역할·인자와 함께 감사 로그에 기록

## 5. 시간 해석

| 규칙 | 근거 |

| 입력은 NFKC 정규화가 0단계 (라우팅에서, D23) | NFD 한글, 전각 숫자가 정규식에 안 걸림 |
| 규칙 파서로만 계산. LLM 폴백 없음 (D21) | 틀린 시각을 지어내는 비용 > 되묻는 비용 |
| 타임존 `Asia/Seoul` 코드 고정 (D22) | 프로세스 TZ 의존 금지 |

| 추측한 것은 전부 사용자에게 표시 | "날짜가 없어 오늘로 봤습니다" |

maintenance 봇의 `src/time/__tests__` 케이스 표를 가져와 Kotlin으로 재구현한다. 코드는 공유하지 않는다.

## 6. 이름 해석

| 규칙 | 근거 |
| --- | --- |
| 완전 일치가 **하나**일 때만 자동 확정 (D24) | `Test Group` / `Test Group 2` 오인 방지 |
| 점수 4단계: 완전 일치 / 앞부분 / 포함 / 겹치는 단어 비율 | 편집 거리는 설명 불가 |
| 그 외는 후보 목록을 보여주고 사용자가 고름 | 한 번 더 고르는 비용이 더 쌈 |
| 별칭은 Kuma 태그, 캐시 금지 (D25) | 태그를 떼면 같은 말이 다른 대상을 가리킴 |

## 7. 세션 (WriteFlow)

| 규칙 | 근거 |
| --- | --- |
| 사용자당 WriteFlow 세션 하나 | 동시에 둘이면 어느 쪽 얘기인지 놓침 |
| 3분 무응답 시 만료 + 주기적 청소 | 오래된 세션이 엉뚱한 발화를 이어받음 |
| 종료 이유 기록: `cancelled` / `expired` / `replaced` / `failed` / `done` | 사용자에게 할 말이 다 다름 |
| 답이 되지 않는 발화는 흘려보냄 (세션 유지) | 되묻기 반복은 시끄러움 |
| 자유 문장 슬롯(제목)은 **되물었고, 그 턴이 다른 슬롯도 채웠을 때만** 수용 | "잠깐 회의 갔다올게"가 제목이 되는 것 방지 |

## 8. 프롬프트에 주입하는 것

- 현재 시각과 기준 타임존 (표시용. 계산은 규칙 파서가 함)
- 사용자 역할과 허용된 도구 목록
- 행동 규칙: 도구 결과에 없는 수치를 지어내지 않는다 / 시간 범위 불명확 시 최근 24시간을 쓰고 그 가정을 명시한다 / 한국어로 짧게 답한다

## 10. 비용 · 테스트

- 월 $20 이하 (D18). 낮은 effort, 도구 반환 상한, 루프 5회 상한
- LLM 제공자는 인터페이스로 추상화 (Claude / GPT 교체 가능)
- **단위 테스트에서 LLM 클라이언트는 반드시 목** (D35)
- 슬롯 추출·시간 파서·이름 해석은 LLM 없이 테스트 가능하도록 분리
