# 04. 인증 · 계정

> 최초 작성: 2026-09-23

## 1. 구조

> **tsidp는 신원의 원천, 패스키는 그 신원의 캐시.**

| 접속 경로 | 로그인 수단 | 비고 |
| --- | --- | --- |
| 테일넷 내부 | tsidp (OIDC) | 주 경로 |
| 외부 도메인 | 패스키 (WebAuthn) | tsidp는 테일넷 안에만 있어 외부에서 도달 불가 |
| tsidp 장애 시 | 패스키 | 폴백 |

비밀번호는 없다 (D26).

## 2. 도메인과 RP ID (D29)

- 접속 도메인: `beacon.prdis.me` 하나
- RP ID: `beacon.prdis.me`
- 테일넷에서는 Tailscale split DNS로 `100.x` 해석, 외부에서는 공개 레코드로 리버스 프록시 해석
- 인증서: Let's Encrypt DNS-01 (서버가 공개 IP 없이도 발급)

ts.net 이름을 쓰지 않는 이유: 테일넷 이름은 바뀔 수 있고, 바뀌면 등록된 패스키가 전부 무효가 된다. RP ID는 한 번 정하면 바꿀 수 없는 값으로 취급한다.

## 3. 계정 생성

```
테일넷에서 tsidp 로그인
  → Beacon이 tsidp 신원(로그인 이름)으로 계정 조회
  → 없으면 생성
       · 로그인 이름 == BEACON_OWNER → Owner
       · 그 외 → Viewer (D32)
```

- 계정은 tsidp 로그인으로만 생긴다. 외부에서 계정이 생기는 경로는 없다
- `BEACON_OWNER`는 환경변수 (D31). "최초 로그인 = 소유자"의 경쟁 조건을 피함

## 4. 패스키

| 규칙 | 근거 |
| --- | --- |
| 등록은 tsidp 세션에서만 (D28) | 신원 확인 없이 패스키가 생기는 경로 차단 |
| 사용자당 여러 개 등록 가능 (기기별) | |
| 계정 비활성화 시 모든 패스키 즉시 거부 | 회수 수단 |
| 신뢰 만료 없음 (D33) | |

패스키 로그인 시 tsidp에 묻지 않는다. 역할은 Beacon DB에서 읽는다 (D30).

## 5. 역할 (D30)

| 역할 | 인원 | 권한 |
| --- | --- | --- |
| Owner | 1명 | 전부 + 사용자 관리 + 어댑터·알림 설정 |
| Operator | 여러 명 | 조회 + 점검 생성·취소 |
| Viewer | 여러 명 | 조회 |

### 5.1 권한 매트릭스

| 동작 | Viewer | Operator | Owner |
| --- | :-: | :-: | :-: |
| 대시보드 조회 | O | O | O |
| 에이전트 읽기 | O | O | O |
| 점검 생성·취소 | | O | O |
| 자기 패스키 관리 | O | O | O |
| 감사 로그 조회 | | O | O |
| 사용자 역할 변경·비활성화 | | | O |
| 어댑터·알림 설정 | | | O |
| Owner 이전 | | | O |

외부(패스키) 세션에서도 Owner 작업을 허용한다 (D34).

### 5.2 보호 규칙

- Owner는 항상 정확히 1명. 강등·비활성화 전에 이전이 선행되어야 함
- 자기 자신의 역할은 변경할 수 없음
- 모든 역할 변경·비활성화는 감사 로그에 기록
- 복구: Owner가 패스키와 tsidp를 모두 쓸 수 없으면 서버 CLI로 이전 (`beacon admin transfer-owner <login>`). 서버 접근 권한이 최종 권한

## 6. 세션

- 로그인 후 서버 세션 쿠키 (`HttpOnly`, `Secure`, `SameSite=Lax`)
- 세션에 로그인 수단(tsidp / passkey)을 기록 — 감사 로그와 화면 표시용
- 역할 변경·비활성화 시 해당 사용자의 기존 세션 즉시 무효화

## 7. 운영 절차

- 팀원이 테일넷에서 제거되면 **Beacon에서도 비활성화한다** (D33 만료 없음의 보완)
- Tailscale ACL로 Beacon 노드 접근을 필요한 사용자로 제한한다 (D32 자동 Viewer의 보완)
