## 2. 경계와 소유권

| 데이터 | 원천 | Beacon의 권한 |
| --- | --- | --- |
| 모니터 목록·상태·이력 | Kuma | 읽기 |
| 점검 일정 | Kuma | 읽기 + kuma-bridge 경유 생성·취소 |
| 별칭 | Kuma 태그 | 읽기 (캐시 금지) |
| 외부 웹훅 이벤트 | Beacon | 소유 |
| 사용자·역할·패스키 | Beacon | 소유 |
| 신원 | tsidp | 읽기 |
| 감사 로그·대화 | Beacon | 소유 |

규칙: **원천이 Beacon이 아닌 데이터는 Beacon에 영구 저장하지 않는다.** 캐시는 허용하되 원천이 항상 이긴다.

## 3. Adapter

Kuma 외의 소스를 코드 구조 변경 없이 붙이기 위한 인터페이스.

### 3.1 역할

어댑터는 원천 시스템의 데이터를 Beacon 공통 모델로 변환한다. 에이전트 도구는 어댑터를 모른다 — 공통 모델만 본다.

### 3.2 공통 모델 (개념)

| 모델 | 필드 (개념 수준) |
| --- | --- |
| Target | 원천 ID, 이름, 별칭 목록, 소속 어댑터 |
| Status | 대상, 상태(UP/DOWN/DEGRADED/UNKNOWN), 응답시간, 관측 시각 |
| StatusEvent | 대상, 이전 상태, 이후 상태, 발생 시각, 해소 시각 |
| Maintenance | 원천 ID, 제목, 시작, 종료, 대상 목록 |
| ExternalEvent | 출처, 제목, 심각도, 리전, 원본 JSON, 수신 시각 |

필드 이름과 타입은 스키마 작성 시 확정한다 (D6).

### 3.3 어댑터가 선언하는 것

- 제공하는 기능 (상태 / 이벤트 / 점검 읽기 / 점검 쓰기)
- 알림 토글 지원 여부와 기본값 (D14: 전부 OFF)
- 연결 상태 (정상 / 끊김 / stale)

### 3.4 초기 어댑터

| 어댑터 | 기능 | 단계 |
| --- | --- | --- |
| KumaAdapter | 상태, 점검 읽기·쓰기, 별칭 | MVP |
| WebhookAdapter | 외부 이벤트 수신 | MVP |
| SentryAdapter | 에러 이벤트 | 확장 (O4) |
| BeszelAdapter | 리소스 지표 | 확장 (O4) |

## 4. kuma-bridge

### 4.1 책임

- Kuma Socket.IO 연결을 **하나** 유지하고 REST로 노출
- 점검 생성의 유일한 경로 (핸드오프 §6의 `createMaintenance()` 단일 경로를 구조로 보장)
- Beacon과 maintenance 봇 두 소비자에게 동일한 계약 제공

### 4.2 접근 제어

- 테일넷 전용 (D15). Tailscale ACL로 Beacon·봇 노드만 허용
- 소비자별 베어러 토큰 (Beacon용 1개, 봇용 1개)

### 4.3 연결이 끊겼을 때

| 요청 | 동작 |
| --- | --- |
| 읽기 | 마지막 캐시 반환 + 응답에 stale 표시 (갱신 시각 포함) |
| 쓰기 | 즉시 실패. 재시도는 호출자 책임 |

Kuma 재시작 때마다 양쪽 소비자에서 원인 모를 에러가 나는 것을 막는다.

### 4.4 첫 계약

핸드오프 §7의 "계약 하나만 고정하고 시작"에 따라, 첫 계약은 **예정된 점검 목록을 JSON으로 읽는다**. 이게 봇과 Beacon 양쪽에서 실제로 쓰이는 것을 본 뒤 계약을 늘린다.

권장 순서: 읽기 전용 → 단방향 알림 → 쓰기(사람 승인 경유).

## 5. 실시간 전달

| 용도 | 방식 | 이유 |
| --- | --- | --- |
| 상태 카드 갱신 | WebSocket | 장기 연결, 다수 클라이언트 브로드캐스트 |
| 에이전트 응답 | SSE | 단방향이면 충분, 요청 단위로 끊김, 프록시 처리 단순 |

## 6. API 규약 (이전 설계에서 유지)

- 성공 `{ "data": … }`, 실패 `{ "error": { "code", "message" } }`
- 모든 시각은 ISO-8601 UTC. 표시 변환은 클라이언트, 해석 기준 타임존은 `Asia/Seoul` 고정 (D22)
- 에러 코드는 대문자 스네이크 (`INVALID_REQUEST`, `NOT_FOUND`, `FORBIDDEN`, `CONFLICT`, `UPSTREAM_UNAVAILABLE`, `ACTION_EXPIRED`, `INTERNAL_ERROR`)
- `FORBIDDEN`은 역할 부족, `UPSTREAM_UNAVAILABLE`은 kuma-bridge·어댑터 끊김

엔드포인트 목록은 스키마와 함께 확정한다.

## 7. 장애 격리

| 장애 | 영향 범위 | 대시보드 |
| --- | --- | --- |
| LLM API | 에이전트 입력창만 오류 배너 | 정상 |
| kuma-bridge | Kuma 어댑터가 stale 표시, 점검 생성 불가 | 마지막 상태로 표시 |
| tsidp | 테일넷 신규 로그인 불가 | 패스키로 로그인 가능 |
| 특정 어댑터 | 해당 어댑터 카드만 오류 | 나머지 정상 |

모니터링 도구의 가용성이 외부 의존성에 묶이면 안 된다.
