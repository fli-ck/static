# 05. 로드맵

> 최초 작성: 2026-09-23
> 최종 발표 약 2026-12-09 (D4). 병행 업무로 밀릴 것을 전제해 **11월 말 완료**를 목표로 잡는다.

## 1. 진행 규칙

1. 각 마일스톤은 **관련 문서를 먼저 갱신**한 뒤 구현한다
2. 마일스톤 종료 시 **사용자 코드 검토**를 받는다. 검토 전에는 다음 마일스톤으로 넘어가지 않는다 (D8)
3. 구현 중 내린 판단은 `00-decisions.md`에 날짜와 함께 추가한다
4. 커밋은 되돌릴 수 있는 작업 단위로 쪼갠다

## 2. 순서의 근거

- **kuma-bridge가 먼저.** Beacon과 봇 양쪽의 전제
- **인증이 에이전트보다 먼저.** 도구 필터링이 역할에 의존
- **읽기가 쓰기보다 먼저.** 핸드오프 §6의 "읽기 전용 → 단방향 알림 → 쓰기"
- **패스키는 뒤쪽.** tsidp만으로 전 기능이 동작한 뒤 폴백을 얹는다

## 4. 마일스톤 상세

| 병행 업무로 전체 지연 | 버퍼 소진 | M8 알림 토글을 먼저 뺀다. 그다음 확장 어댑터 |

## 6. 발표에서 빼도 되는 순서

일정이 무너질 때 잘라내는 순서. 위에서부터 뺀다.

1. 알림 토글
2. 대화 원문 30일 정리 작업 (수동 처리로 대체)
3. 패스키 (tsidp만으로 데모)
4. 웹훅 수신

에이전트 읽기·점검 쓰기·역할 필터링은 빼지 않는다 — 이게 빠지면 프로젝트가 성립하지 않는다 (D5).
